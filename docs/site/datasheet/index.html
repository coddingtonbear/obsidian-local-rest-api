Capabilities

What the API can reach

Because the server runs inside Obsidian, it can reach things a folder of markdown does not contain: the resolved metadata cache, the file you currently have open, and the command palette.

Files, in full

Create, read, update, and delete any file in the vault, including binary attachments, plus directory listings.

GET PUT PATCH POST DELETE /vault/{path}

Sections, in isolation

Read or write one heading, block reference, or frontmatter field without fetching or rewriting the whole note.

GET PUT POST PATCH /vault/{path}/heading/{…}

The active file

Operate on whatever note is open in front of you, without knowing its path in advance.

GET PUT PATCH POST DELETE /active/

Search, two ways

Obsidian's own fuzzy search with scored context snippets, or a JsonLogic expression over each note's metadata.

POST /search/simple/ · POST /search/

Commands

List every registered Obsidian command and execute any of them, exactly as the command palette would.

GET /commands/ · POST /commands/{id}/

Tags and the UI

Enumerate every tag in the vault with usage counts, or tell Obsidian to open a particular note on screen.

GET /tags/ · POST /open/{path}

Section-level editing

PATCH is the reason people stay

An instruction names an operation (replace, prepend, append, delete), a scope (the node's content, its marker, both, or its place in the tree), and a target (a heading path, a block id, a frontmatter key). Heading levels in your content are rebased for you; whitespace is normalised for you; an ifMatch token makes the write conditional on the file being unchanged.

JSON instruction

{
  "targetType": "heading",
  "target": ["Work", "Log"],
  "operation": "append",
  "content": "- Shipped the release",
  "ifMatch": "<version from the document map>"
}

Or move the fields out of the body

# Target in the URL, operation in a header,
# body is the raw payload — nothing to escape.
curl -k -X PATCH \
  -H "Authorization: Bearer $KEY" \
  -H "Operation: append" \
  -H "Content-Type: text/markdown" \
  --data "- $TEMPLATED_LINE" \
  …/vault/daily.md/heading/Log

Raw-content mode exists because clients that template markdown — Shortcuts, Tasker, a shell script — should not have to JSON-escape it. Both forms drive the same engine.

MCP server

Sixteen tools, already inside the app

The Model Context Protocol server is part of the plugin, not a separate process wrapping it. Connect any Streamable HTTP client to /mcp/ with the same bearer token, and it gets the same live vault the REST API does.

  • vault_list
  • vault_read
  • vault_write
  • vault_append
  • vault_patch
  • vault_delete
  • vault_move
  • vault_copy
  • vault_get_document_map
  • active_file_get_path
  • search_query
  • search_simple
  • tag_list
  • command_list
  • command_execute
  • open_file

The server also publishes its own OpenAPI specification as an MCP resource, so a capable client can read the full API contract without being told about it.

Comparison

Against the alternatives

Three architectures are commonly used to get an agent into an Obsidian vault. They are not equivalent, and the differences are mostly about what the server can see.

Architectures compared
  This plugin Filesystem MCP server Third-party REST wrapper
Obsidian's resolved tags, links, frontmatter Live metadata cache Re-parsed from disk Whatever this plugin returns
Writes seen by the running app Written through Obsidian's vault API Written behind Obsidian's back Whatever this plugin does
Single-section edits Heading, block, or field, with ifMatch Typically whole-file rewrite Only what it exposes of this plugin
Obsidian commands and UI List, execute, open notes Out of reach Only if it proxies them
Non-MCP clients curl, Shortcuts, browser extensions MCP only MCP only
Processes to install and run The plugin A server, kept up to date A server, plus this plugin
Usable with Obsidian closed No Yes No

Stated plainly: this is a door into a running Obsidian. That last row is the cost, and the rest of the table is what it buys. Note also that the widely used third-party Obsidian MCP servers are wrappers that call this plugin's REST API — if you are running one, you are already running this.

Quick start

From install to first request

Enable the plugin, then open Settings → Local REST API to copy your API key.

1 · Check the server

curl -k https://127.0.0.1:27124/            # status, no auth required

2 · Read something

curl -k -H "Authorization: Bearer $KEY" \
  https://127.0.0.1:27124/vault/Projects/API.md/heading/Log

3 · Connect an agent

claude mcp add --transport http obsidian https://127.0.0.1:27124/mcp/ \
  --header "Authorization: Bearer $KEY"

# Cursor, Claude Desktop, and any other Streamable HTTP client
# use the same URL and the same header.

Extensions

Other plugins can add to it

A plugin can register authenticated routes, public routes, and MCP tools on this server. Install the published types as a dev dependency and the entire host surface is checked at compile time — the declarations are generated from the plugin's own source, so they cannot drift from what is actually running.

Install

npm install --save-dev obsidian-local-rest-api

Use

import { getAPI } from "obsidian-local-rest-api";

const api = getAPI(this.app, this.manifest, 2);
api?.addRoute("/mine/").get(handler);

Questions

Before you install

Does Obsidian need to be running?

Yes. Everything the plugin offers beyond plain file access — the metadata cache, the active file, commands, Obsidian's own search — exists only inside a running app.

How exposed is the server?

It binds to 127.0.0.1 by default, and every route except the status check requires a bearer API key. The certificate is generated on your machine. The plain-HTTP port is off unless you enable it.

Why the certificate warning?

The certificate is self-signed, because it is issued locally for a loopback address. Trust it from https://127.0.0.1:27124/obsidian-local-rest-api.crt, pass it to your client directly, or use the optional plain-HTTP port.

Does it work on mobile?

No — desktop only. The plugin needs Node's TLS and HTTP server APIs, which Obsidian's mobile runtime does not provide.

What does it cost?

Nothing. MIT licensed, open source, installed from Obsidian's community plugin browser.
