Three marketing site directions

Same facts and same calls to action in each; the difference is who they are pitched at and how they argue. Pick one, and it gets promoted to the site root — see docs/site/README.md for how that is done without breaking the existing docs URL.

  • The wire terminal

    Dark and developer-facing, built around a live request/response transcript. Argues that the API is concrete and immediate. Modelled on obsidian.md and make.md.

  • The datasheet datasheet

    Light, dense, and reference-like: a spec block, a contents rail, and the full endpoint matrix on the page. Argues that the thing is thoroughly documented. Modelled on the docs-style plugin sites.

  • The exchange conversation

    Editorial and agent-facing, built around what an agent actually does to a vault. Argues from outcomes rather than endpoints. Modelled on Copilot for Obsidian and Smart Connections.
The published interactive API reference stays where it is: coddingtonbear.github.io/obsidian-local-rest-api.
